# Фоновая многопоточная конвертация WebP-снимков

## Суть
Сейчас `export_scene_snapshots` (controller/export_controller.rb:107) выполняется синхронно внутри `LayoutBuilder.export` (step 5b, service/layout_builder.rb:217–225) — до записи YAML, авто-открытия PDF и `onExportSuccess`. Из-за этого окно «PDF создан» и открытие файла ждут конвертации всех снимков.

Делаем: после `doc.export` главная подготовка (раскладка PNG-исходников) проходит быстро, конвертация PNG→WebP уходит в пул фоновых потоков (libvips потокобезопасна, SketchUp API из фона не трогается), PDF открывается сразу. Прогресс фоновой конвертации — в статусной строке SketchUp (`Sketchup.status_text=`, паттерн уже используется в плагине).

## Изменения по файлам

**1. NEW `dn1c_export_pdf2/service/snapshot_worker.rb` — module Service::SnapshotWorker**
- `submit(jobs, images_dir:, &on_done)` — потокобезопасно (Mutex): дожидается завершения предыдущей партии (join), создаёт пул из N потоков (N = clamp(Etc.nprocessors/2, 2..4)), каждый берёт задания из Queue.
- Задание: `VipsService.png_to_webp(src, dst_tmp)` где `dst_tmp = "NN_Name.tmp.webp"` (libvips выбирает формат по расширению), затем атомарный `File.rename` в `NN_Name.webp` и удаление `NN.png`-исходника. При ошибке конвертации PNG остаётся = PNG-снимок (тот же фолбэк, что сейчас); ошибка пишется в `@errors` + warn.
- `drain` — join всех потоков партии (no-op если ничего не идёт); `status` → `{running:, total:, done:, failed:}`.
- Индикация: после submit запускается повторяющийся `UI.start_timer(0.5, true)` (главный поток, безопасно): `Sketchup.status_text = "DN1C Export PDF: WebP-снимки: 2/5…"`, по завершении — финальный текст («готовы (5)» / «готовы с ошибками (2), сцены сохранены в PNG») и `UI.stop_timer`. Все вызовы UI/Sketchup — с guards `defined?(UI)`/`respond_to?`, в автономных тестах таймер просто не заводится.
- vips_init — однократно в главном потоке до старта пула (см. п.2), чтобы потоки не соревновались за мемоизацию.

**2. `service/vips_service.rb`** — добавить публичный `ensure_started!` (обёртка `available? && init!`) для прогрева в главном потоке перед стартом пула.

**3. `controller/export_controller.rb` — переработка `export_scene_snapshots(reusable: {}, async: true, &progress_block)`:**
1. `SnapshotWorker.drain` (прошлая партия не должна пострадать от очистки папки) → `mkdir_p` + очистка `*.{png,webp}` как сейчас.
2. По каждой сцене (с прогресс-сообщениями «Подготовка снимка сцены i/N»): источник = reusable PNG из кэша PDF-страниц → **FileUtils.cp** в `images/NN_Name.png` (важно: оригиналы-времянки удаляются в ensure LayoutBuilder, строки 250–253), либо `render_scene_png` → mv в `images/`. То есть все исходники живут в папке снимков под финальными именами ещё до выхода из экспорта.
3. Если libvips недоступна — PNG-снимки уже записаны, возвращаем их (как сейчас).
4. Если доступна: собираем jobs `{src: NN.png, dst: NN.webp}`; `async: true` (по умолчанию, production-путь) → `SnapshotWorker.submit`, возврат планируемых путей сразу; `async: false` (тесты/отладка) → те же jobs конвертируются инлайн синхронно (текущее поведение).
- Существующие `write_scene_webp`/фолбэк-логика переиспользуются в inline-режиме; в worker — вызов VipsService напрямую.

**4. `service/layout_builder.rb`** — только комментарий step 5b (вызов не меняется, асинхронность включена по умолчанию).

**5. Тесты**
- `comprehensive_test.rb`: после экспортов в тестах 69/71/71b добавить `SnapshotWorker.drain` перед проверками файлов; новый тест воркера: submit нескольких заданий с реальным vips → drain → webp на месте, исходники PNG удалены, счётчики status, фолбэк на битом PNG, повторный submit/drain идемпотентны.
- `test_export.rb`: drain после экспорта + проверка итогового webp.

**6. `version.rb`** — 2.1.0 → 2.2.0.

## Проверка
- `ruby -I dn1c_export_pdf2 dn1c_export_pdf2/test/comprehensive_test.rb` и `test_export.rb` — все зелёные.
- Бенчмарк GVL: конвертация N PNG пулом 1 vs 4 потока через vendored DLL (если Fiddle держит GVL, параллелизм будет ограничен — зафиксируем честно; корректность не зависит).
- В SketchUp (ext_reload): экспорт → PDF открывается сразу, в статусной строке отсчёт «WebP-снимки: k/N», папка images наполняется фоном, повторный экспорт во время конвертации не ломает файлы.

## Риски / ограничения (честно)
- Резкое закрытие SketchUp посреди конвертации — останутся `.png`/`.tmp.webp`; при следующем экспорте папка очищается (glob уже покрывает `.tmp.webp`).
- Гибридный (векторный) режим: рендер сцен обязан идти в главном потоке (SketchUp API) — фоновым уходит только PNG→WebP; в режиме image (по умолчанию) исходники уже готовы и выигрыш максимальный.
