Ускорение создания снимков сцен (PNG/высокое разрешение) — убираем двойной рендер и бесполезную переупаковку

## Причины медленности (подтверждено кодом)
При текущих настройках (render_quality: high, page_size: A3 → 4961px, image_format: jpg) каждая сцена:
1. Рендерится в JPG для страницы PDF (layout_builder.rb:897), затем рендерится ВТОРОЙ раз в PNG для снимка, потому что `reusable_source` (export_controller.rb:239) принимает только `.png`.
2. PNG пережимается `optimize_png_lossless` (render_service.rb:243,257) — Zlib BEST_COMPRESSION на ~18 Мп в чистом Ruby, секунды CPU на сцену — и результат выбрасывается, т.к. PNG сразу конвертируется в lossy WebP Q85.

## Изменения

### 1. dn1c_export_pdf2/controller/export_controller.rb
- `reusable_source` (строки 234–242): добавить параметр `allow_jpeg:` — принимать `.jpg/.jpeg` наравне с `.png`, когда снимок всё равно уйдёт в lossy WebP.
- `export_scene_snapshots` (строки 114–169):
  - `reuse_jpeg = webp_mode && !webp_opts[:lossless]` — JPEG-заготовка переиспользуется только для lossy WebP (при lossless WebP и без libvips — прежнее поведение с PNG-рендером, чтобы не терять качество/формат);
  - расширение промежуточного файла брать из источника (`File.extname(src)`) вместо жёсткого `.png`;
  - glob очистки папки images (строка 125) расширить до `*.{png,jpg,jpeg,webp}`;
  - в `render_scene_png` передавать `optimize_png: false`, когда PNG является промежуточным для lossy WebP.
- Комментарии методов привести в соответствие.

### 2. dn1c_export_pdf2/service/render_service.rb
- Строка 243: `optimize_png_lossless(temp_file) if rendered && !is_jpeg && options[:optimize_png] != false`.

### 3. Тесты — dn1c_export_pdf2/test/comprehensive_test.rb
- Новый тест: image-режим + image_format jpg + lossy WebP → `render_scene_temp` вызывается 1 раз на сцену (счётчик через singleton-прокси, как в существующих тестах ~5990), снимок `.webp` создаётся.
- Новый тест: lossless WebP → JPEG не переиспользуется, рендерится PNG.
- Новый тест: libvips недоступна → JPEG не переиспользуется (снимок PNG, как раньше).
- Прогнать comprehensive_test.rb, убедиться что существующие тесты снимков не сломаны.

## Что НЕ меняется
Качество и формат итоговых снимков (WebP при наличии libvips, иначе PNG), рендер страницы PDF (JPG Q100), фоновую конвертацию SnapshotWorker, drain(3.0), настройки.

## Ожидаемый эффект
На сценарии по умолчанию на каждую сцену вместо двух рендеров 4961px + zlib-9 остаётся один рендер: этап снимков ~2.5–3x быстрее, весь экспорт примерно в 2 раза.

Примечание (без правок кода): время одного рендера определяет SketchUp write_image при 4961px + antialias; если скорость важнее качества печати — render_quality: medium (150 dpi) в настройках даёт в 4 раза меньше пикселей.
