Хранение: `saveData` → SessionStore → `config/layout.yaml`; данные строк — `InfoLineResolver`.

**Подтверждённые дефекты:**
1. **`[object Object]`** — `app.js:2295` и `app.js:146–153`: Ruby присылает стадионы как массив объектов `{name, status}`, а JS умеет только legacy-кортежи и делает `String(st)`. Правильный образец уже есть: `app.js:2594` (`st.name`).
2. **Превью даты ≠ PDF**: футер показывает `toLocaleDateString()` → «9/22/2026» (en-US), средний блок — ISO «2026-09-22», PDF — dd.mm.yyyy.
3. **«Последние изменения»**: превью берёт старейшую запись истории (`h[h.length-1]`, app.js:167), Ruby-экспорт — новейшую (`.first`).
4. `item_order` влияет только на превью (порядок в PDF задаётся `line_rows`/`lines`); drag его переписывает попутно с `lines`/`line_rows` — учесть в тестах.

## Этап 1 — Исправления диалога (`dn1c_export_pdf2/dialog/html/app.js`)
1. `:2295` — ветка объекта: `(st && st.name !== undefined) ? st.name : (Array.isArray(st) ? st[2] : String(st))`.
2. `:146–153` — то же + статус: `` `${st.status ? "[✓]" : "[ ]"} ${st.name}` `` (легаси-кортежи оставить).
3. Хелпер даты `dd.mm.yyyy` и выравнивание источников с Ruby (`last_edit_date || date`) в: `:156–159` (workflow_date), футер-строки (`:184/193`, `footerItemsDef` ≈2467), средний блок (`:2298`, `:2597`).
4. `:165–169` — «Последние изменения»: брать первую (новейшую) запись `h[0]`, как в Ruby.

## Этап 2 — Автотесты каждого параметра (mock LayOut)
- Усилить `test/mock_sketchup.rb`: `Layout::Document` регистрирует созданные экземпляры (`Document.instances`) — тесты получат доступ к сущностям с `bounds`/`style`/`rtf_data`/`text`.
- Новый файл `test/test_template_params.rb` (включить в общий прогон; стиль — как в comprehensive_test.rb):
  - **Шапка**: Вкл on/off; valign top/center/bottom (позиции по bounds); состав включённых строк; группировка «стр. 1–5» (одна RTF-строка, разделитель « \| », порядок внутри строки); «пт.» (`\fs` = pt×2 в rtf_data); цвета (colortbl в rtf_data).
  - **Средний блок**: Вкл; «Все»/«Снять» (lines); «Заголовок» on/off (префикс названия); ⇤/⇥ (левая/правая колонка по x bounds); ↑⇕↓ (зоны по y); пер-строчный размер/цвет; «Расстояние мм» (зазор между соседними bounds ≈ mm→pt); стадионы → чекбоксы `[✓]`/`[ ]` (`draw_stadia_check_rows`).
  - **Подвал**: Вкл; font_size; Слева/Центр/Справа (три бакета с разными x); «Страница N \| M» на каждой странице; нижний якорь.
  - **Данные**: «Версия 01 # Ревизия 001», артикул, дата dd.mm.yyyy, история (новейшая запись).
- Контрактный тест: `to_h[:workflow][:stadia]` сериализуется как `[{name:, status:}]` — форма, которую ждёт JS.
- Guard-тесты на app.js (в духе существующих include?-проверок) для каждого исправленного места.
