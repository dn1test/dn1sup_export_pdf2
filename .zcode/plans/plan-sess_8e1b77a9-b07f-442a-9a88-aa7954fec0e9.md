# Стадии проекта: создание, удаление и drag-and-drop сортировка

## Суть
В панели «Стадии проекта» (вкладка «Данные проекта») добавить:
1. **Создание** дополнительных (пользовательских) стадий — поле ввода + кнопка «+ Добавить» под списком, новая стадия добавляется в конец списка без отметки.
2. **Удаление** любой стадии крестиком у строки (кроме последней оставшейся).
3. **Перетаскивание мышкой** для изменения порядка стадий (HTML5 drag-and-drop, как у таблицы сцен).
4. **Дефолт при создании нового проекта** (нет project.yaml): отмечена только «Предварительный проект» (сейчас в коде отмечены первые три).

Порядок стадий значим: он определяет порядок строк блока «Стадия проекта» на PDF-листах, а статус проекта берётся по последней отмеченной стадии — поэтому после перемещения/удаления статус пересчитывается.

## Изменения

### 1. `dn1c_export_pdf2/model/project_data.rb`
- `default_stadia` (строки 376–387): оставить `status: true` только у «Предварительный проект», у остальных семи — `false`.
- Других правок Ruby не нужно: `normalize_stadia` (392–423) уже пропускает произвольный список `[{name, status}]`, и он же по существующей цепочке автосохранения попадает в `project.yaml`.

### 2. `dn1c_export_pdf2/dialog/html/index.html`
- В панели `workflow-stadia-panel` (187–197) после `#stadiaCheckboxesContainer` добавить строку: `<input type="text" id="inputNewStadia">` + кнопку `<button id="btnAddStadia">+ Добавить</button>`.

### 3. `dn1c_export_pdf2/dialog/html/app.js`
- В карте `els` (~559) зарегистрировать `inputNewStadia`, `btnAddStadia`.
- `renderStadia()` (5597–5654):
  - обновить JS-фолбэк `defaultStadia` (5601–5610) — только первая стадия `true`;
  - в каждой строке: имя обернуть в `span.stadia-name`, добавить кнопку удаления `.stadia-delete` (×, видна при наведении; скрывается, когда стадия одна);
  - drag-and-drop по образцу таблицы сцен (5489–5565): mousedown-гард (перетаскивание не начинается с `input`/`button`), `dragstart/dragend/dragover/dragleave/drop` с индикаторами вставки верх/низ; по drop — splice `state.workflow.stadia`, перерисовка, `notifyChange()`;
  - удаление: `preventDefault/stopPropagation` (чтобы не щёлкнулся чекбокс), splice, запрет удаления последней стадии, перерисовка, `notifyChange()`;
  - вынести пересчёт статуса «по последней отмеченной стадии» (5631–5643) в хелпер и вызывать его также после удаления и перемещения.
- Инициализация (~6236, рядом с другими кнопками): клик по `btnAddStadia` и Enter в `inputNewStadia` → добавить `{name: trim, status: false}` в конец (пустое имя игнорируется), очистить ввод, перерисовать, `notifyChange()`.

### 4. `dn1c_export_pdf2/dialog/html/app.css`
- Рядом со стилями стадий (4008–4058): `.stadia-checkbox-item.dragging` (полупрозрачность), `.drag-over-top`/`.drag-over-bottom` (индикаторная полоска), `.stadia-name` (flex:1), `.stadia-delete` (×, появляется при наведении), `.stadia-add-row` (ввод + кнопка в один ряд, компактные размеры под панель).

## Что не меняется
- `service/info_line_resolver.rb` — рисует стадии в порядке массива (`[✓] Имя` / `[ ] Имя`), пользовательские имена подхватятся автоматически.
- Цепочка сохранения/загрузки project.yaml и существующие проекты (у них остаётся свой сохранённый список).
- Сэмпл `project.yaml` в корне репозитория (данные пользователя).

## Проверка
1. `ruby -c` на изменённый project_data.rb.
2. Hot-reload расширения в живом SketchUp через sketchup-dev MCP (ext_reload), открыть диалог и проверить: добавление стадии (кнопка и Enter), drag-and-drop порядок, удаление, пересчёт статуса проекта, дефолтные галки, сохранение списка в project.yaml.
3. Убедиться, что PDF-блок «Стадия проекта» отражает новый состав и порядок (при экспорте).
