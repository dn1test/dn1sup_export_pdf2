# Запись артикула в файл модели (.skp)

## Суть

При создании артикула записывать его в сам .skp через атрибутный словарь SketchUp (`model.set_attribute`), а при открытии модели — читать артикул оттуда и по нему определять папку проекта `<папка .skp>/<Артикул>`. Сейчас связь модель→проект определяется только эвристикой файловой системы (`Dir.glob(<папка .skp>/*/project.yaml)`, работает лишь при ровно одной папке артикула) — при 0 или 2+ папках модель не сопоставляется с проектом.

Это меняет прежний дизайн «атрибуты .skp не используются» (комментарии в project_data.rb:19, session_store.rb:12 и тест-запрет comprehensive_test.rb:4247-4250). В .skp храним **только артикул** — тип торговли выводится из префикса (CF#/HF#), остальные данные остаются в YAML. Сохранение .skp — за пользователем (уведомление + Ctrl+S), автосохранение модели не делаем.

## Изменения по файлам

1. **НОВЫЙ** `dn1c_export_pdf2/model/model_articul_store.rb` — модуль `Model::ModelArticulStore`:
   - `DICT_NAME = "DN1C_ExportPdf2"`, `KEY_ARTICUL = "Articul"`;
   - `write(model, articul)` — `model.set_attribute(...)`, guard `respond_to?` + rescue (никогда не ломает основной поток);
   - `read(model)` — `model.get_attribute(DICT_NAME, KEY_ARTICUL, "")`.
   Используются именно `get_attribute`/`set_attribute` — они уже есть в тестовом моке (mock_sketchup.rb:255-262), `attribute_dictionary` в моке нет.

2. **`main.rb`** — `require_relative "model/model_articul_store"` перед project_data (test также подтянет через `../main`).

3. **`model/project_data.rb`**:
   - `load_auto` (строка 1192): новый **шаг 0** — прочитать артикул из .skp; если он есть, установить `@project_info[:articul]` (прокси сам выведет commercial/trade из префикса) и загрузить `project.yaml` / legacy `<Артикул>.yaml` из `articul_dir_for_model`. Если загрузилось — старая цепочка обнаружения (glob ровно одной папки, legacy-поиск) пропускается; если папки артикула нет — старая цепочка работает как фолбэк. Остальное (edit_history, нормализация) без изменений;
   - `save_project_yaml` (строка 1267): после успешной записи YAML — `ModelArticulStore.write(model, @project_info[:articul])` (покрывает: создание через `createProjectFolder`, сохранение кнопкой, flush при экспорте и при закрытии SketchUp, смену артикула через импорт);
   - обновить комментарии-запреты: строки 19, 1189, 1241-1242 («в .skp хранится только артикул через ModelArticulStore»).

4. **`model/session_store.rb`** — в `import_project_yaml` после установки сессии: `ModelArticulStore.write(model, pd.project[:articul])`; обновить комментарий строки 12.

5. **`dialog/export_dialog.rb`** — в callback `createProjectFolder` сразу после установки артикула (строка 152): `ModelArticulStore.write(model, articul) if model`. Пишется и при несохранённой модели (папку создать нельзя, но атрибут в памяти — попадёт в файл при первом Ctrl+S).

6. **`dialog/html/app.js`** — `onProjectFolderCreated` (строка 6702): дополнить уведомление напоминанием «сохраните .skp (Ctrl+S), чтобы артикул остался в файле модели».

7. **`test/comprehensive_test.rb`** (строки 4247-4250):
   - негативные проверки project_data.rb **сохранить** (прямой API атрибутов — только в новом модуле), обновить формулировки;
   - добавить позитивные: существует `model_articul_store.rb`; `ModelArticulStore` упоминается в project_data.rb / session_store.rb / export_dialog.rb;
   - функциональный тест на MockModel: `save_project_yaml` записывает артикул в атрибуты; `load_auto` определяет папку по артикулу из .skp **даже при двух папках артикулов рядом** (главный новый сценарий), и фолбэкится на старое обнаружение, если папки из .skp нет.

## Поведение после изменения

- Создали артикул → project.yaml записан, артикул в атрибутах модели; Ctrl+S → артикул навсегда в .skp.
- Открыли такой .skp где угодно → панель сразу знает артикул и папку проекта (модалка создания не показывается), даже если рядом с моделью несколько папок артикулов или ни одной.
- Старые модели (артикул только в YAML) работают как раньше; артикул попадёт в .skp при следующем сохранении из плагина.
- Папку артикула удалили/переименовали → фолбэк на прежнее обнаружение.
