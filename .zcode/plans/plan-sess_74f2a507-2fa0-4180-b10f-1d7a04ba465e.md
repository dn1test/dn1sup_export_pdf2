## Проверка работы шаблонов и параметров шаблонов (dn1c_export_pdf2)

Контекст: недавний рефакторинг (незакоммиченный) заменил старые блоки header/slot_N/footer на систему пользовательских параметров шаблона (`custom_layouts[тип].params`: источник, label, align/valign, шрифт/размер/цвет, visible, группы). Проверяю всю цепочку: YAML-конфиг → резолв источников → отрисовка зон → живой PDF.

### Этап 1 — Офлайн-тесты (терминальный Ruby, mock SketchUp)
Из корня репо:
- `ruby -I dn1c_export_pdf2 dn1c_export_pdf2/test/test_template_params.rb` — тесты 79–84 (зоны, источники, изоляция шаблонов, YAML round-trip, группы)
- `ruby -I dn1c_export_pdf2 dn1c_export_pdf2/test/comprehensive_test.rb` — полный набор (77 тестов)
- При фейлах — разбор причины, правка кода, повторный прогон.

### Этап 2 — Синтаксис под Ruby SketchUp (3.2)
- `ext_check` изменённых Ruby-файлов (layout_builder.rb, info_line_resolver.rb, project_data.rb) — синтаксис 3.2 в мостовом интерпретаторе.

### Этап 3 — Живая проверка в SketchUp (мост sketchup-dev MCP)
Если мост офлайн — этап пропускается с пометкой в отчёте.
1. `status` → `console_eval`: загрузка регистратора плагина.
2. Через `console_eval` — scratch `ProjectData` с тестовыми данными (проект/заказчик/workflow/стадии/папки спецификации/несколько сцен с разными типами страниц), экспорт матрицы PDF в `.tmp_live_check/`:
   - все 6 зон размещения (left/center/right × top/bottom), несколько параметров в зоне, зазоры;
   - группы (`" | "` join), label вкл/выкл, `visible:false` и пустые значения пропускаются;
   - источники: `project.*`, `customer.*`, `workflow.*` (включая `workflow.stadia` с чекбоксами), `dir.N.title/description`, `scene.name/description`, `page.number_total`, `page.toc`;
   - шрифты/размер/цвет, кастомный шаблон с собственными params (изоляция между шаблонами);
   - round-trip `layout.yaml`: load → save → load.
3. PDF→PNG (pymupdf), визуальная проверка страниц.

### Этап 4 — Отчёт
Сводка: что работает / найденные проблемы (с путями к коду), пути к PDF/PNG артефактам. Найденные баги правятся и перепроверяются прогоном затронутых тестов + повторным экспортом.
