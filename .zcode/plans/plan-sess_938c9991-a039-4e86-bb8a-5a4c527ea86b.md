# WebP-снимки сцен через libvips (Fiddle, без гемов)

## Архитектура решения

SketchUp не умеет писать WebP напрямую (`view.write_image` — только png/jpg), а LayOut не вставляет WebP в PDF. Поэтому: рендер остаётся PNG (темп-файл, он же переиспользуется PDF-пайплайном), а **конвертация PNG→WebP происходит при записи снимков в папку артикула**. libvips подключается напрямую через **Fiddle** (плагин уже так вызывает gdi32/user32 в `font_service.rb`) — без ruby-vips и ffi-гемов, которые несовместимы со встроенным Ruby SketchUp.

## Изменения по файлам

### 1. Новый `dn1c_export_pdf2/service/vips_service.rb`
Модуль `Service::VipsService` с ленивым `require "fiddle"`:
- `available?` (мемоизировано) — ищет DLL **только в папке плагина**: `<plugin>/vendor/libvips/`, имена `libvips-42.dll` (свежие сборки 8.15+), `libvips-0.dll` (старые). Не найдено → false.
- `png_to_webp(src, dst, quality: 85)` — биндит 5 функций: `vips_init`, `vips_image_new_from_file`, `vips_image_write_to_file`, `g_object_unref`, `vips_error_buffer`. Перед dlopen — разовый prepend `vendor/libvips` в `ENV["PATH"]` (иначе Windows-загрузчик не найдёт DLL-зависимости glib).
- Вызовы: `new_from_file(src_utf8, NULL)` → `write_to_file(img, "dst.webp[Q=85]", NULL)` → `g_object_unref(img)`. Путь и опции передаются строкой UTF-8 — glib на Windows сам конвертирует в wide-char, кириллица в путях артикулов работает. Ошибка → чтение `vips_error_buffer`, warn, удаление битого файла, возврат nil.

### 2. `controller/export_controller.rb`
- `scene_png_dir` → `scene_images_dir`: `<Артикул>/images` (имя независимо от формата, по ответу пользователя). Старую папку `png/` не трогаем.
- `export_scene_pngs` → `export_scene_snapshots`:
  - очистка: `Dir.glob("images/*.{png,webp}")` вместо `*.png` (строка 112);
  - формат из `pdf_settings[:snapshot_format]` ("png" | "webp"), расширение файла снимка по формату (строка 143);
  - при webp: временный PNG → `VipsService.png_to_webp(src, target, quality: settings[:webp_quality] || 85)` → удалить темп. Если libvips недоступен/ошибка конвертации — **фолбэк на PNG** с одним warn (снимки не теряются).

## Не трогаем
Формат рендера для PDF (`image_format`, селект PNG/JPEG), `optimize_png_lossless`, JPG-превью сцен в диалоге, папки `pdf/`, `skp/`, `_last.pdf`.

## Итог для пользователя
Положил DLL libvips в `vendor/libvips` → выбрал «WebP» в диалоге → в `<Артикул>/images/` вместо PNG появляются `.webp` (в ~5-10 раз меньше файлов). Нет DLL — всё работает как раньше, с PNG и предупреждением.
