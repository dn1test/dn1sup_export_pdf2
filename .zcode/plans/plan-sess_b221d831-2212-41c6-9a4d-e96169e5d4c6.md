Эмпирическая проверка вариативных шрифтов из config/fonts_new и вердикт об использовании при экспорте PDF.

Шаг 1. GDI-проба (без установки шрифтов в систему): Ruby/Fiddle-скрипт — приватная загрузка каждого VF (AddFontResourceExW, FR_PRIVATE, только в рамках процесса) + EnumFontFamiliesExW: какие имена семейств/начертаний Windows отдаёт по VF (видны ли named instances "Oswald Light", "SemiBold" и т.д.), GetTextFaceW/GetGlyphIndicesW — резолвятся ли имена и есть ли кириллица на каждом face.

Шаг 2. Тест в живом SketchUp/LayOut (через dev-мост sketchup-dev): временно установить VF штатным механизмом FontService (ensure_font_installed! после обновления карты файлов), собрать тестовый Layout::Document — все 4 семейства × default + named instances, строки с кириллицей и Ø × ² —, doc.export в PDF; прогнать PdfFontAudit.audit_exported_pdf! (что реально встраилось в /BaseFont), отрендерить страницы в PNG и проверить визуально рендер и веса. После теста — убрать VF из системы (файлы из user-fonts + записи реестра HKCU Fonts + RemoveFontResourceW).

Шаг 3. Отчёт-вердикт по каждому из 5 шрифтов: работает/не работает, какой face видит LayOut, что встраивается в PDF, меняется ли вид (Oswald Light vs Regular).

Шаг 4 (по итогам шага 3, с отдельного согласования): если VF работают — интеграция: перенос VF в config/fonts, офлайн-переименование name-таблицы SofiaSansExtraCondensed VF в "Sofia Sans ExtraCond" (fonttools или Ruby-патчер name-таблицы), обновление AVAILABLE_FONTS / LAYOUT_FACE_NAMES / LAYOUT_FONT_CANDIDATES в font_service.rb, тестов и README; решение по Oswald ("Oswald Light" vs Regular). Если LayOut с VF не справляется — рекомендация: остаться на текущих статиках (fonts_new не подключать), при желании веса получить инстансированием VF в статические TTF офлайн.

Проверка изменений: прогон тестового харнесса плагина (test/comprehensive_test.rb) внутри SketchUp после любых правок FontService.
