## Переделка параметров шаблонов: динамический каталог из заполненных данных

### Суть
Сейчас списки добавления параметров жёстко зашиты в трёх местах `app.js` (шапка — 5 пунктов, средний блок — 10+папки, подвал — 5) и показываются всегда, с текстовыми заглушками («Фасады МДФ, ЛДСП, Blum...», «CF#260905_160129»). Резолвер (`info_line_resolver.rb`) тоже возвращает заглушки вместо пустоты.

Делаем **один динамический каталог параметров**, который строится из фактически заполненных данных и показывается во всех трёх блоках. Пункт есть в списке ⇔ его данные заполнены. Заглушки убираются полностью; пустые строки не печатаются на PDF (рендер-циклы в `layout_builder.rb` уже пропускают nil — строки 1136, 1442, 1664).

### Новый каталог (порядок = группы)

**Структурные (всегда в списке):** `toc_pages` «Содержание (список страниц)», `scene_name` «Название сцены», `footer_page_total` «Страница | Страниц» — только в блоке «Подвал».

**Проект (паспорт объекта)** — пункт только если поле заполнено: `articul` (практически всегда — обязателен), `furniture_name` «Изделие», `room_name` «Помещение», `address` «Адрес установки», `customer_company` «Компания», `project_desc` «Описание проекта».

**Заказчик:** `customer_id` «ID заказчика», `customer_name` «Заказчик», `customer_phone` «Телефон», `customer_email` «Email».

**Workflow:** `workflow_author` «Автор», `workflow_price` «Стоимость», `workflow_dates` «Сроки» (если есть хотя бы одна дата), `workflow_duration` «Длительность», `workflow_version` «Версия» и `workflow_revision` «Ревизия» (всегда есть значение), `workflow_date` «Дата» (всегда — текущая), `footer_last_edit` «Последние изменения» (если заполнен last_edit или история), `workflow_history` «История правок» (если записи есть), `workflow_stadia` «Стадия проекта» (если список стадий не пуст).

**Папки и спецификации:** `dir_desc_N` «📁 <имя папки>» — только для папок с непустым описанием; `dir_specs` «📁 Все спецификации папок» — если есть хотя бы одно описание; `spec_materials` «Материалы и фурнитура», `spec_appliances` «Техника и подсветка», `spec_lighting` «Подсветка» — по заполненности производных полей (их наполняет синхронизация папок в `project_data.rb`).

**Сцены:** `scene_description` «Описание сцены» — только если заполнено.

Составные пункты убираются из списков: `place_address`, `customer_or_company`, `footer_ver_rev`, `footer_rev_ver_date`, `footer_articul`, `footer_date` (вместо них — отдельные поля). **Обратная совместимость:** резолвер продолжает понимать старые ключи (уже сохранённые `layout.yaml` не ломаются), но тоже без заглушек.

### Изменения по файлам

1. **`dialog/html/app.js`**
   - Вместо `AVAILABLE_INFO_LINES` + трёх зашитых списков — одна функция `buildParamCatalog(info, wf)`: возвращает `{key, label, preview, group}` только по заполненным данным; `getInfoLineDef(key)` ищет в ней (+ динамические `dir_desc_N`/`dir_specs`). Убрать все fallback-заглушки в `getVal`.
   - Шапка/средний блок/подвал (`renderTemplateSettingsList`) получают один и тот же каталог; в подвал добавляется `footer_page_total`. Предпросмотр на канве — реальные значения, пустые строки не рисуются.
   - `DEFAULT_LINES_BY_CONTENT`, `DEFAULT_HEADER_SLOT`/`DEFAULT_MIDDLE_SLOT` — перевести на отдельные ключи (`room_name`, `address`, `customer_name`...).
   - При сохранении (`saveData`-сборка `:checked`): сохранённые ключи, чьи строки сейчас скрыты (данные опустели), не выбрасываются из конфига — мержатся обратно. На PDF они не выводятся, в списке не видны, при заполнении данных возвращаются.
   - Удалить мёртвый код `renderSlotCardHtml`/`fullAvailableLines` (не вызывается).

2. **`service/info_line_resolver.rb`**
   - `resolve`, `resolve_parts`, `resolve_header_item`: пустое значение → `nil` (никаких «Материалы: Фасады МДФ...», «ПРОЕКТ МЕБЕЛИ», «Заказчик не указан», «—»). Префиксы («Ревизия: X», «Тел: X») остаются, когда значение есть.
   - Составные `place_address`/`customer_or_company` — оставить для старых шаблонов, но nil, если обе части пусты.

3. **`service/layout_builder.rb`** — дефолтные строки шапки (строка 1103) и маппинг номеров строк (1123–1129) дополнить новыми отдельными ключами. Рендер-циклы уже пропускают nil/пусто — не трогаем.

4. **`model/project_data.rb`** — `default_custom_layouts` (510–596): дефолтные линии новых шаблонов на отдельные ключи.

5. **`test/test_template_params.rb`** — обновить контракт: пустые данные → nil (нет заглушек), каталог в JS строится динамически (проверки-гарды на строки app.js переписать), добавить кейс «пункт отсутствует в DOM-списке, но сохранён в конфиге».
