## Локальные правила репозитория

Правила обязательны в каждой сессии. Выполнять без напоминаний и без дополнительных вопросов.

### 1. Версионирование — после КАЖДОЙ правки кода

После любых правок плагина повышать `PLUGIN_VERSION` в `dn1sup_export_pdf2/version.rb`:

- **Добавлена новая функция** (новая вкладка, новый механизм, новая кнопка с новой логикой, новый колбэк моста) → увеличить **вторую** цифру и обнулить третью: `2.9.0 → 2.10.0`.
- **Изменения незначительные** (дизайн, верстка, выравнивание, мелкие фиксы, тексты/локализация, правка только фронтенда) → увеличить **третью** цифру: `2.9.0 → 2.9.1`.

Делать это в той же сессии, где сделаны правки, до сдачи результата. Не оставлять «на потом» и не ждать явной просьбы.

### 2. Доставка правок в SketchUp (один id)

Пользователь видит плагин из каталога Plugins SketchUp (`%APPDATA%/SketchUp/SketchUp <год>/SketchUp/Plugins`), а не из dev-репозитория. Двойников с суффиксом `_dev` больше нет — правки доставляются под тем же id (полные правила — мастер `U:\dn1code\sketchup_ext\AGENTS.md`):

1. Пересобрать GUI: `npm run build` в `frontend/`.
2. `ruby update_from_dev.rb` — копия рабочей папки в Plugins под тем же id
   (или пункт меню «🔄 Обновить из рабочей копии...»).
3. «⚡ Перезагрузить расширение (Hot Reload)» — горячая перезагрузка без
   рестарта SketchUp. При открытой панели экспорта — закрыть и открыть её
   заново (HtmlDialog читает html при открытии).

### 3. Проверки после правок

- `ruby test/comprehensive_test.rb` из `dn1sup_export_pdf2` — структурные тесты грепают исходники Vue и Ruby, изменения не должны их ломать.
- Визуальная проверка GUI — через браузер на mock-данных (собранный `dialog/html` на статическом сервере): верстка, RU/EN, отсутствие прокрутки.
