# DN1C Export PDF 2 (SketchUp API 2026)

**DN1C Export PDF 2** — современное, расширяемое расширение для Trimble SketchUp 2026, предназначенное для профессионального формирования презентационных и технико-коммерческих многостраничных PDF-документов из сцен 3D-модели.

---

## 🌟 Ключевые возможности

1. **Модульная архитектура шаблонов страниц**:
   - 📕 **Титульный лист (`cover`)**: Крупное название проекта, реквизиты заказчика, статус, контактные данные, основной превью-рендер модели и таблица истории ревизий.
   - 📝 **Описание и спецификации (`description`)**: Структурированные блоки спецификаций (*Материалы и фурнитура*, *Подсветка и электрика*, *Пояснительная записка*) с акцентными плашками и рендером сцены.
   - 📑 **Пояснительная записка и содержание (`explain`)**: Автоматически генерируемое оглавление проекта с номерами листов, спецификации материалов и примечания к проекту.
   - 🖼️ **Визуализация (`visual`)**: Максимизированное изображение сцены высокого разрешения с минималистичным статусным баннером.
   - 📐 **Технический / Общий вид (`general`)**: Стандартное оформление чертежей и видов с рамками, примечаниями и колонтитулами.

2. **Нативная генерация через SketchUp LayOut Ruby API (Без внешних гемов)**:
   - 📐 **SketchUp LayOut API**: Создает полноценный многостраничный документ LayOut (`.layout`) со встроенными живыми видовыми экранами `Layout::SketchUpModel`, привязанными к сценам модели SketchUp.
   - 🎨 **Режимы рендеринга видовых экранов**:
     - **Гибридный (Hybrid)**: Идеальное сочетание четких векторных линий и фотореалистичных текстур/теней.
     - **Векторный (Vector)**: Прецизионная векторная графика с высочайшей резкостью линий чертежа.
     - **Растровый (Raster)**: Быстрый рендеринг растровых видов и текстур.
   - 🗂️ **Структурированные слои LayOut**:
     - `DN1C_Viewports` — живые 3D-видовые экраны модели SketchUp.
     - `DN1C_Graphics` — фоновые разделители, акцентные плашки и рамки.
     - `DN1C_Content` — форматированный типографический текст и информационные блоки.
     - `DN1C_Annotations` — водяные знаки, статусы утверждения и штампы.
   - 💾 **Сохранение `.layout` проекта**: При экспорте создается не только итоговый PDF-документ, но и файл проекта `.layout` рядом с ним для открытия и доработки в Trimble LayOut.
   - 🚀 **100% автономность**: Полное отсутствие сторонних гемов (`prawn`, `pdf-core`, `ttfunk`), нет проблем с компиляцией C-расширений или установкой RubyGems.

3. **Интерактивный пользовательский интерфейс (`UI::HtmlDialog`)**:
   - Современный интерфейс с вкладками: *Данные проекта*, *Страницы* (с управлением видовым экраном и пропорциями кадра каждой сцены), *Шаблоны* (сайдбар шаблонов и WYSIWYG-редактор слотов), *Папки и спецификации*, *История*, *Настройки*.
   - Тонкая настройка LayOut экспорта: режим рендеринга видовых экранов (Hybrid, Vector, Raster), сохранение `.layout` файла, качество вывода.
   - Индивидуальная настройка каждой сцены (включение/выключение, выбор шаблона страницы, примечания к виду, пропорции кадра 3:2 / 4:3 / 16:9 / 1:1 / На весь лист, изменение порядка страниц).
   - Выбор формата листа (`A3`), ориентации (`Альбомная`, `Книжная`).
   - Настройка водяных знаков / штампов (`НЕ УТВЕРЖДЕН`, `В ПРОИЗВОДСТВО`, пользовательский текст, отключение).
   - Цветовая кастомизация акцентов и штампа.
   - Импорт и экспорт настроек в формат YAML.
   - Прогресс-бар экспорта в реальном времени.

4. **Синхронизация и сохранность данных (YAML)**:
   - **Предложение создать артикул при открытии панели**: если проект еще без артикула, при открытии диалога сразу предлагается выбрать тип проекта — «Коммерческий» (артикул `CF#…`) или «Бытовой» (`HF#…`). После выбора создается папка проекта `<Артикул>` рядом с рабочим файлом `.skp` и в нее записывается `project.yaml`; там же хранятся PDF, резервные копии SKP и снимки сцен.
   - **Данные проекта — только в папке артикула**: файл данных называется `project.yaml` и хранится внутри папки проекта `<базовая папка|папка .skp>/<Артикул>/project.yaml`. Якорные копии YAML рядом с `.skp` не создаются.
   - **Артикул обязателен**: без артикула данные проекта не сохраняются. При попытке сохранения или экспорта без артикула показывается модалка его создания (сгенерированный `CF#`/`HF#` можно отредактировать); в сценариях без диалога (закрытие SketchUp, быстрый экспорт) YAML проекта просто не записывается, настройки расширения сохраняются как обычно.
   - **Обнаружение проекта при открытии .skp**: сканируются подпапки рядом с моделью (`<папка .skp>/*/project.yaml`) — если папка артикула одна, проект загружается автоматически; если несколько, выбор делается через «Импорт YAML». Проекты старых версий (`.yaml`-якорь рядом с `.skp`, `<Артикул>/<Артикул>.yaml`) остаются читаемыми и мигрируют в `project.yaml` при первом сохранении, а старые дубликаты удаляются.
   - **Журнал правок**: `edit_history.yaml` читается из папки артикула, при отсутствии — из папки `.skp` (совместимость).
   - **Двухуровневое хранение и приоритеты чтения**:
     - 🥇 **Первично**: YAML файлы (данные проекта — `project.yaml` в папке артикула; настройки программы — `settings.yaml`/`layout.yaml` внутри расширения).
     - 🥈 **Вторично**: Библиотека файла (словарь атрибутов SketchUp `DN1C_ExportPDF`) не используется.
   - **Чистые поля по умолчанию**: Все поля метаданных изначально пусты и содержат наглядные подсказки (`placeholders`), без захардкоженных тестовых данных.
   - Автоматическое сохранение резервной копии `.skp` модели с номером ревизии в папку `<Артикул>/skp/`.
   - Автоматическое сохранение сгенерированного PDF документа (версионная копия в `<Артикул>/pdf/`, рабочая копия `_last.pdf` рядом с `.skp`) и открытие в PDF-просмотрщике по умолчанию.

5. **Профессиональная типографика (5 свободных кириллических шрифтов и автозамена)**:
   - 🔤 **5 свободных вариативных шрифтов в комплекте** (полные права встраивания в PDF `fsType: 0x0000`; VF-файлы содержат все начертания от Thin до Black в одном файле):
     - `Sofia Sans Condensed` — основной чертежный узкий шрифт по умолчанию (SIL OFL 1.1).
     - `Sofia Sans Extra Condensed` — сверхсжатый узкий шрифт для емких спецификаций и таблиц (VF переименован в семейство `Sofia Sans ExtraCond` для корректного выбора в LayOut).
     - `Oswald` — строгий классический гротеск (свободная открытая замена коммерческого DIN).
     - `Roboto Condensed` — современный технологичный гротеск от Google (Apache 2.0).
     - `Ubuntu Condensed` — компактный технический шрифт от Canonical (Ubuntu Font Licence 1.0).
   - 🅱️ **Параметр начертания `font_weight`**: `normal` (Обычное) или `bold` (Жирное) — применяется ко всему тексту PDF. Вариативные шрифты дают настоящее жирное начертание (Bold 700), встраиваемое в PDF отдельным сабсетом.
   - ↔️ **Параметр ширины `font_width`**: `condensed` (Узкая) или `extra_condensed` (Сверхузкая) — повышает сжатие базового семейства `Sofia Sans Condensed` до `Sofia Sans Extra Condensed`. Для `Oswald`, `Roboto Condensed` и `Ubuntu Condensed` ширина фиксированная.
   - 🔄 **Бесшовная замена DIN Condensed**: Устаревший `DIN Condensed` заменен на `Oswald`. В сохраненных конфигурациях и проектах ссылки на `DIN Condensed` автоматически заменяются на `Oswald`.
   - 🛡️ **Отказоустойчивый шрифтовой Fallback**: Если запрошенный шрифт не установлен и не может быть развернут в системе, LayOut Builder производит автоматическую подстановку доступного шрифта из комплекта (`Sofia Sans Condensed`, `Sofia Sans Extra Condensed`, `Oswald`, `Roboto Condensed`, `Ubuntu Condensed`). Системные шрифты Windows (Arial, Segoe UI, Verdana и т.п.) сознательно не используются: плагин работает только с собственным комплектом из `config/fonts`.
   - 🧹 **Миграция со статических шрифтов**: при первом экспорте плагин удаляет из пользовательской папки шрифтов и HKCU-реестра статические файлы прежних версий (`Oswald-Light.ttf`, `SofiaSansCondensed-Regular.ttf`, `SofiaSansExtraCond-Regular.ttf`, `SofiaSansExtraCondensed-Regular.ttf`, `RobotoCondensed-Regular.ttf`), чтобы старые копии не затеняли вариативные шрифты.

## 🚀 Установка и использование

### Установка в SketchUp 2026:
1. Скопируйте файл `dn1c_export_pdf2.rb` и папку `dn1c_export_pdf2/` в каталог плагинов SketchUp:
   - **Windows**: `C:\Users\<Имя_Пользователя>\AppData\Roaming\SketchUp\SketchUp 2026\SketchUp\Plugins\`
2. Перезапустите SketchUp или выполните в Ruby Console:
   ```ruby
   load 'dn1c_export_pdf2.rb'
   ```
3. На панели инструментов появится группа кнопок **DN1C PDF Export 2**, а также пункт в меню **Plugins** (Расширения).

### Запуск автономных тестов в терминале:
```powershell
ruby -I dn1c_export_pdf2 dn1c_export_pdf2/test/comprehensive_test.rb
```
